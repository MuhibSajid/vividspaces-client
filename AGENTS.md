# VividSpaces

Peer-to-peer studio booking marketplace (photo studios, sound stages, podcast rooms). Next.js 16 App Router in `src/`, single npm package — no workspaces, no test framework.

## Commands

- `npm run dev` / `npm run build` / `npm run lint` — all npm, never yarn/pnpm (npm lockfile only).
- No `typecheck` script; run `npx tsc --noEmit`. Verify changes with `npm run lint && npx tsc --noEmit` (lint and types are the only checks — there are no tests).
- `.env` is required before dev/build: `src/lib/auth.ts` opens its MongoDB client at module load, so the app crashes without `MONGODB_CLIENT_URL` (Atlas URI), plus `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL`. The file is gitignored but tracked in git anyway — don't treat it as disposable.

## Framework quirks

- Tailwind v4, CSS-first: there is no `tailwind.config`; theme tokens live in `@theme` in `src/app/globals.css`, including a custom `coral` color palette used across components.
- `next.config.ts` enables `cacheComponents`, `reactCompiler`, and `partialPrefetching`. With `cacheComponents`, wrap async/server data in `<Suspense>` (see `src/app/page.tsx`).
- Turbopack loads Tailwind via the `@tailwindcss/turbopack` rule in `next.config.ts`; don't add PostCSS config.

## shadcn/ui

- Components in `src/components/ui/` are generated by the shadcn CLI (`npx shadcn add <component>`) using the `base-nova` style — they build on `@base-ui/react`, **not** Radix. Base UI uses a `render` prop instead of Radix's `asChild`; follow existing usage, don't copy Radix examples.
- Aliases (`@/components`, `@/lib`, `@/hooks`) come from `components.json`.

## Auth: real backend, mock UI (early stage)

- Server: `better-auth` + `mongodbAdapter` in `src/lib/auth.ts` (db `vividspaces`), mounted at `src/app/api/auth/[...all]/route.ts`, client in `src/lib/auth-client.ts`.
- The UI does **not** use it yet: `src/hooks/use-auth.ts` returns a hardcoded `MOCK_USER`, so the navbar always shows a fake logged-in user.
- Navbar links point to `/login` and `/register`, but the only auth pages are empty placeholders (`src/app/signin/page.tsx`, `src/components/signup/page.tsx`). Route names are inconsistent (signin vs login); expect broken links until pages are built.
- Unbuilt routes referenced by the navbar: `/studios`, `/dashboard`, `/add-studio`, `/my-listings`, `/my-bookings`.
